# 实验配置与 Run 接口设计

配置保存、版本查询和 Run 启动已接入 REST、Web、助手审批与 Runner 定向路由。Run 查询及 Job 明细见[实验创建与查询](实验创建与查询.md)。

实验配置每次有实际改动才新增版本。启动 Run 时，用户选择具体配置版本和该数据集版本中的 Example。同一个配置版本可以运行多次，每次 Run 独立保存实际数据集版本、样本修订和执行快照。

## 1. 通用约定

- 下文路径均以 `/api/v1` 为前缀。所有请求须有登录 Cookie，POST 还须通过 CSRF 和来源校验。配置、数据集、版本、评分器、Runner 和 Run 都按当前用户归属校验。资源不存在或不可访问时返回 `404`。
- `group_id` 是 `config_group_id` 的 UUID，标识整组配置。启动路径里的 `config_id` 是配置版本行的整数主键。其余 ID 规则沿用[通用约定](接口文档.md#通用约定)。
- 响应使用 JSON 和 `Cache-Control: no-store`。分页统一返回 `{items, page, pagesize, total}`，默认 `page=1`、`pagesize=20`，每页最多 100 条。

## 2. 配置接口

| 方法与路径 | 请求 | 成功响应 |
| --- | --- | --- |
| `POST /experiment-configs` | 完整配置对象 | `201`，返回该组的 v1 |
| `GET /experiment-configs` | `page`、`pagesize`、可选 `dataset_id` | `200`，每组一条最新版，按最新版的创建时间、ID 倒序。Dataset 筛选作用于最新版 |
| `GET /experiment-configs/{group_id}` | 路径中的组 ID | `200`，返回该组的最新版 |
| `GET /experiment-configs/{group_id}/versions` | `page`、`pagesize` | `200`，按版本号倒序分页，每条包含完整配置和版本主键 |
| `POST /experiment-configs/{group_id}/versions` | `{base_version, config}`，`config` 为完整配置对象 | 有差异返回 `201` 和新版本，相同返回 `200` 和现有版本 |

创建 v1 请求示例。保存新版时，同一个对象放进请求的 `config` 字段，并附上编辑开始时读取到的 `base_version`。

```json
{
  "name": "订单 Agent 回归",
  "description": "验证订单查询",
  "dataset_id": 12,
  "dataset_version_id": null,
  "runner_id": "runner-01",
  "agent_target_id": "order-agent",
  "timeout_seconds": 60,
  "stream_output": true,
  "repetitions": 2,
  "evaluators": []
}
```

| 字段 | 约束 |
| --- | --- |
| `name`、`description` | 名称必填，去除首尾空白后 1–100 字符。描述可空，最多 2,000 字符 |
| `dataset_id`、`dataset_version_id` | Dataset 必填，版本省略或为 `null` 表示每次启动前选取具体版本。固定版本须属于该 Dataset |
| `runner_id`、`agent_target_id` | 均必填。Agent 目标是 Runner 本地配置中的名字 |
| `timeout_seconds`、`stream_output`、`repetitions` | 默认分别为 `60`、`false`、`1`。超时范围为 `(0, 3600]` 秒，重复次数为 1–100 |
| `evaluators`、`dataset_evaluator_ids` | 可直接提交评分器定义或引用当前 Dataset 下已有的评分配置。两种非空列表互斥，最多 100 项，要求评分器名称或引用 ID 唯一 |

响应保留配置字段，增加 `id`、`config_group_id`、`version`、`created_at`。`evaluators` 返回服务端展开的快照。内置项包含输入映射、`dataset_evaluator_id` 和 `output_configs`。自定义项以 `kind: "CODE"` 和 `code_evaluator_version_id` 绑定发布版本，快照还记录评分器 ID、名称和版本号。请求结构见[评分器选用](接口文档.md#在实验配置中选用)。

保存新配置或新版配置时，评分器必须未归档，发布版本必须归当前用户所有。归档后可继续从已有配置版本启动 Run。

```json
{
  "id": 23,
  "config_group_id": "d1e4dbd7-a656-4981-9b02-46678b398bf4",
  "version": 1,
  "name": "订单 Agent 回归",
  "description": "验证订单查询",
  "dataset_id": 12,
  "dataset_version_id": null,
  "runner_id": "runner-01",
  "agent_target_id": "order-agent",
  "timeout_seconds": 60,
  "stream_output": true,
  "repetitions": 2,
  "evaluators": [],
  "created_at": "2026-11-19T08:00:00Z"
}
```

## 3. Run 接口

| 方法与路径 | 请求 | 成功响应 |
| --- | --- | --- |
| `POST /runners/{runner_id}/experiment-configs/{config_id}/runs` | 必填 `dataset_version_id`，可选 `example_ids` | `201`，Run 详情。响应头 `Location: /api/v1/experiments/{experiment_id}` |
| `GET /experiment-runs` | 分页及可选的配置组、版本、状态筛选 | `200`，当前用户的 Run 摘要分页 |
| `GET /experiment-configs/{group_id}/runs` | `page`、`pagesize`、可选正整数 `version` | `200`，该组 Run 摘要分页，按创建时间、ID 倒序 |
| `GET /datasets/{dataset_id}/experiments` | 沿用现有分页参数 | `200`，按数据集查询 Run，返回增强后的摘要 |
| `GET /experiments/{experiment_id}` | 既有 Run ID | `200`，返回增强后的 Run 详情 |
| `POST /experiments/{experiment_id}/cancel` | 既有 Run ID，无请求体 | `200`，取消提交后的 Run 详情 |

增强后的摘要和详情在现有字段上增加 `experiment_config_id`、`config_group_id`、`config_version`，沿用 `experiment_id` 表示 Run ID。`dataset_version_id` 表示本次实际版本，`progress` 统计本次选中样本及生成的 Job，详情继续返回执行配置与评分器快照。旧字段形状见[现有实验详情](实验创建与查询.md#3-查询实验详情)。

```http
POST /api/v1/runners/runner-01/experiment-configs/23/runs
```

```json
{
  "dataset_version_id": 37,
  "example_ids": [42, 57]
}
```

启动成功时的 Run 详情示例：

```json
{
  "experiment_id": 101,
  "experiment_config_id": 23,
  "config_group_id": "d1e4dbd7-a656-4981-9b02-46678b398bf4",
  "config_version": 1,
  "dataset_id": 12,
  "dataset_version_id": 37,
  "name": "订单 Agent 回归",
  "description": "验证订单查询",
  "status": "pending",
  "repetitions": 2,
  "progress": {
    "example_count": 2,
    "job_count": 4,
    "queued": 4,
    "assigned": 0,
    "running": 0,
    "succeeded": 0,
    "failed": 0,
    "cancelled": 0,
    "unknown": 0,
    "evaluations": {"expected": 0, "completed": 0, "errors": 0}
  },
  "execution_config": {
    "runner_id": "runner-01",
    "agent_target_id": "order-agent",
    "timeout_seconds": 60,
    "stream_output": true
  },
  "evaluators": [],
  "metadata": {},
  "created_at": "2026-11-19T08:05:00Z",
  "updated_at": "2026-11-19T08:05:00Z"
}
```

- `example_ids` 省略表示该版本全部有效样本。显式提交时须为非空且无重复的 Example ID 列表。以配置中的重复次数为 2 为例，选中上述两条样本将写入 1 个 Run、2 条样本快照和 4 个 Job。
- 前端使用现有 `GET /datasets/{dataset_id}/examples` 取样本。固定版本直接传 `version_id`。选择「最新」时，首次查询取返回的实际 `dataset_version_id`，之后翻页和启动 Run 都传这个版本。
- Job 列表、详情和 SSE 路径继续使用 `/experiments/{experiment_id}/jobs` 下的[现有接口](接口文档.md#job-查询)。
- 普通创建 `POST /datasets/{dataset_id}/experiments` 和旧定向创建 `POST /runners/{runner_id}/datasets/{dataset_id}/experiments` 作为兼容入口，在同一事务内创建独立 v1 和全量 Run。新 Web 入口先保存配置，再启动 Run。启动 POST 当前无幂等键，客户端需防止双击并避免超时后自动重发。

| 状态码 | 触发条件 |
| --- | --- |
| `404` | 配置组、版本、Dataset、数据集版本或 Runner 不存在或不可访问 |
| `409` | 编辑时 `base_version` 已过期，提示重读最新版。Run 创建服务发现 Runner 离线、禁用或能力不满足时沿用相应错误 |
| `422` | 路径 Runner 与配置不符，固定版本与提交版本不符，样本范围无效、没有有效样本或生成 Job 数超限 |
| `403` / `503` | 定向部署中，代理路由拒绝未就绪的 Runner，或目标实例暂时无法提供其会话 |

### 实验 Run 列表

`GET /api/v1/experiment-runs` 需要登录 Cookie，请求体为空。默认列出当前用户跨配置组、跨数据集的所有 Run，按 `created_at DESC, experiment_id DESC` 排序。

| 查询参数 | 类型 | 默认值及约束 |
| --- | --- | --- |
| `page` | integer | 默认 `1`，正整数 |
| `pagesize` | integer | 默认 `20`，范围 1–100 |
| `group_id` | UUID | 可选，按配置组筛选 |
| `version` | integer | 可选，按配置版本号筛选，正整数。省略 `group_id` 时匹配所有可访问组的该版本号 |
| `status` | string | 可选，取 `pending\|running\|cancelling\|completed\|failed\|cancelled` |

筛选条件可组合。配置组不存在或不可访问返回 `404 experiment_config_not_found`，参数无效返回 `422 invalid_request`，未登录返回 `401 not_authenticated`。可访问范围内无匹配记录或页码超出范围时返回 `200` 和空 `items`。 `total` 始终是筛选后的总数。

```http
GET /api/v1/experiment-runs?group_id=d1e4dbd7-a656-4981-9b02-46678b398bf4&version=1&status=completed&page=1&pagesize=20
```

成功响应为 `{items, page, pagesize, total}`。每条 `items` 使用现有 [Run 摘要结构](实验创建与查询.md#2-按数据集列出实验)，包含 Run ID、配置组和版本、实际数据集版本、状态、Job 进度与时间。

## 4. 配置服务改动

1. 新增配置路由、请求与响应模型、配置服务。校验当前用户及 Dataset、版本、Runner 的归属，展开评分器引用并冻结映射与输出定义。保存允许 Runner 离线，启动时再判断执行能力。
2. 首次保存生成组 UUID，插入 `version=1`。保存新版时，在事务内锁定该组的 v1，读取最新版本并核对 `base_version`。比较去空白、补默认值及展开评分器后的配置内容。相同返回现有行，有变化才插入 `version+1`，保留历史行。数据库联合唯一约束防止版本冲突。
3. 查询 Run 时通过 `experiment_config_id` 连接具体配置版本。按组查询覆盖该组的所有版本，可按版本筛选。列表和详情读取该次 Run 的运行状态和快照。

## 5. Run 创建服务与调用方

1. `ExperimentService.start_run()` 按当前用户读取具体配置版本。核对路径 Runner、实际数据集版本、Runner 归属和启用状态，从 Redis 检查在线状态。流式执行沿用现有的 `http_json` 和 `http_sse` 能力要求。
2. 沿用 `dataset_snapshot()` 计算实际版本中的有效样本。局部执行按请求的 Example ID 取交集，任何一个 ID 未匹配都拒绝整次请求。校验 `样本数 × repetitions ≤ 10,000`。
3. 在同一个短事务中写入 Run（`pending`）、所选样本及修订和 Job（`queued`）。Run 引用具体配置行，保存实际数据集版本，并将该配置版本的执行参数与评分器快照写入 `execution_config`。提交后按 Runner ID 和 Run ID 通知 Scheduler。Job 成功后，评分待办根据快照中的发布版本 ID 读取源码，交给 Snekbox 评分，结果写入 Job 评分明细。
4. 更新 Nginx 和 `/internal/runner-route` 的创建路径匹配，继续用路径里的 Runner ID 路由到持有就绪会话的实例。在业务路由重新验证当前实例的会话与配置归属。Job SSE 路由继续使用现有规则。
5. Web 的配置编辑、版本选择、样本选择和启动各自调用对应接口。助手的 `EXPERIMENT_start_run` 待审批参数记录配置版本主键、Runner ID、实际数据集版本和样本范围。批准时浏览器通过 `POST /runners/{runner_id}/assistant/stream` 将原有审批请求发给持有 Runner 会话的实例，继续沿用[助手 SSE 协议](../assistant-sse.md)。同一轮批准的启动操作使用同一个 Runner。服务在领取审批前校验本地会话，并使用同一套 Run 创建逻辑执行。

实现见[配置服务](../../evalforge/server/services/experiment_configs.py)、[Run 服务](../../evalforge/server/services/experiments.py)和 [Runner 定向路由](../../evalforge/server/routes/internal_routing.py)。数据库升级见[迁移说明](../../migrations/versions/README.md)。
