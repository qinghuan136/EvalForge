# 实验创建与查询接口（V1）

本文说明已实现的三个 REST 接口。登录与错误格式沿用[现有 API 约定](登录鉴权与Runner管理.md)，数据结构对应[实验 ORM](../../evalforge/db/orm/experiments.py)。入口与事务逻辑见[实验路由](../../evalforge/server/routes/experiments.py)和[实验服务](../../evalforge/server/services/experiments.py)。

| 方法 | 路径 | 成功响应 |
| --- | --- | --- |
| POST | `/api/v1/datasets/{dataset_id}/experiments` | `201`，创建后的实验详情 |
| GET | `/api/v1/datasets/{dataset_id}/experiments` | `200`，实验摘要分页 |
| GET | `/api/v1/experiments/{experiment_id}` | `200`，实验详情 |

## 通用约定

- 三个接口均先校验浏览器登录 Cookie。POST 再校验 `X-CSRF-Token` 和请求来源：有 `Origin` 时使用它，否则取 `Referer` 的来源，均须命中允许列表。Runner 的 WSS Bearer 凭据不能用于这些接口。
- 请求体和响应体使用 JSON；成功响应直接返回资源或分页对象，不另包 `data`。时间使用 UTC ISO 8601，响应包含 `Cache-Control: no-store`。
- `dataset_id`、`dataset_version_id`、`experiment_id` 是 1–2147483647 的整数，对应现有 ORM ID。实验归属由服务端根据登录身份填写，创建请求不接收 `user_id`、`status`、`job_id` 或 `attempt_id`。
- 创建和列表接口仅允许访问当前用户拥有的数据集。V1 没有共享数据集规则，`datasets.user_id` 为空的历史数据集不视为公开资源。数据集版本按所属数据集校验，不能引用其他数据集的版本。
- 详情仅查询当前用户拥有的实验。不存在与无访问权限统一返回 `404`；查询不会泄露其他用户的记录、样本内容或运行结果。

## 1. 创建实验

`POST /api/v1/datasets/{dataset_id}/experiments`

路径中的 `dataset_id` 指定用于创建实验的数据集，请求体不重复携带该字段。未列出的请求字段一律拒绝，包括 `execution_config` 内的未知字段。

| 请求字段 | 类型 | 必填 | 约束与默认值 |
| --- | --- | --- | --- |
| `name` | string | 是 | 去除首尾空白后为 1–100 字符；允许同名实验 |
| `description` | string 或 null | 否 | 默认 null，最多 2,000 字符 |
| `dataset_version_id` | integer | 否 | 指定该数据集的版本；省略时在创建事务内选定该数据集已提交的最大版本 ID |
| `repetitions` | integer | 否 | 默认 1；V1 取值 1–100，每个有效样本生成对应次数的 Job |
| `metadata` | JSON object | 否 | 默认 `{}`；仅用于记录实验附加信息，不参与派发 |
| `execution_config` | object | 是 | 本次实验的执行配置，创建时保存 |
| `execution_config.runner_id` | string | 是 | 1–128 字符，非纯空白；指定当前用户拥有、已启用且未删除的 Runner，允许其离线 |
| `execution_config.agent_target_id` | string | 是 | Runner 本地配置中的 Agent 目标名，去除首尾空白后为 1–128 字符 |
| `execution_config.timeout_seconds` | number | 否 | 默认 60；有限正数，V1 上限 3,600 秒，表示每次 Agent 调用的超时 |

请求示例（数据集 `12`）：

```json
{
  "name": "订单 Agent 回归",
  "description": "验证订单查询和取消",
  "dataset_version_id": 37,
  "repetitions": 2,
  "metadata": {"purpose": "regression"},
  "execution_config": {
    "runner_id": "runner-01",
    "agent_target_id": "order-agent",
    "timeout_seconds": 60
  }
}
```

### 创建语义

1. 校验数据集、版本与 Runner 归属。云端保存 `agent_target_id`，不接收 Agent URL、HTTP 请求头或本地凭据。创建时不要求 Runner 在线，也不探测该目标是否已经配置在客户端。
2. 固定选定版本的有效样本：对每个样本，取该数据集内 `dataset_version_id <= 选定版本 ID` 的最新修订，然后排除最新修订为 `DELETE` 的样本。新版本只改动部分样本时，未改动的样本仍使用它此前的有效修订。
3. 在同一个数据库事务内写入 `Experiment`（状态 `pending`）、`ExperimentDatasetExample`（每个样本对应的修订 ID），以及每个「样本 × 重复序号」的 `ExperimentRun`（状态 `queued`，序号从 1 开始）。没有有效样本时拒绝创建；V1 单次创建最多 10,000 个 Job，超限同样拒绝，不留下部分记录。
4. 事务提交成功后返回 `201 Created`。不创建 `RunnerAttempt`，不调用 WSS，不执行 Agent 或评分。后续版本的数据集修改不会改变本实验所选的版本及修订引用。

V1 暂不支持创建幂等键；重复提交 POST 可能创建多个实验。请求超时不能证明创建没有成功，客户端不应盲目自动重发。

### 成功响应：`201 Created`

响应头：`Location: /api/v1/experiments/101`。响应体与详情接口结构相同。示例中版本有 3 个有效样本，每个执行 2 次：

```json
{
  "experiment_id": 101,
  "dataset_id": 12,
  "dataset_version_id": 37,
  "name": "订单 Agent 回归",
  "description": "验证订单查询和取消",
  "status": "pending",
  "repetitions": 2,
  "metadata": {"purpose": "regression"},
  "execution_config": {
    "runner_id": "runner-01",
    "agent_target_id": "order-agent",
    "timeout_seconds": 60
  },
  "progress": {
    "example_count": 3,
    "job_count": 6,
    "queued": 6,
    "assigned": 0,
    "running": 0,
    "succeeded": 0,
    "failed": 0,
    "cancelled": 0,
    "unknown": 0
  },
  "created_at": "2026-11-08T02:00:00Z",
  "updated_at": "2026-11-08T02:00:00Z"
}
```

## 2. 按数据集列出实验

`GET /api/v1/datasets/{dataset_id}/experiments?page=1&pagesize=20`

无请求体。路径参数为 `dataset_id`；分页与 Runner 管理一致。

| 查询参数 | 类型 | 默认值 | 约束 |
| --- | --- | --- | --- |
| `page` | integer | 1 | 1–2147483647 |
| `pagesize` | integer | 20 | 1–100 |

只返回当前用户在该数据集下创建的实验，覆盖该数据集的所有版本。按 `created_at DESC, experiment_id DESC` 排序。不冻结跨请求分页快照。数据集可访问但没有匹配实验，或页码超出范围时，返回 `200` 和空 `items`；`total` 仍表示符合条件的总记录数。

### 成功响应：`200 OK`

每个摘要与详情共享 ID、名称、状态、重复次数、进度及时间字段；不展开描述、元数据或执行配置，也不附带样本、Job、Attempt 或评分明细。

```json
{
  "items": [
    {
      "experiment_id": 101,
      "dataset_id": 12,
      "dataset_version_id": 37,
      "name": "订单 Agent 回归",
      "status": "pending",
      "repetitions": 2,
      "progress": {
        "example_count": 3,
        "job_count": 6,
        "queued": 6,
        "assigned": 0,
        "running": 0,
        "succeeded": 0,
        "failed": 0,
        "cancelled": 0,
        "unknown": 0
      },
      "created_at": "2026-11-08T02:00:00Z",
      "updated_at": "2026-11-08T02:00:00Z"
    }
  ],
  "page": 1,
  "pagesize": 20,
  "total": 1
}
```

## 3. 查询实验详情

`GET /api/v1/experiments/{experiment_id}`

输入只有路径参数 `experiment_id`，无请求体或分页参数。返回 `200 OK`，响应字段与[创建实验的成功响应](#成功响应201-created)相同：摘要字段加 `description`、`metadata`、`execution_config`。

- `status` 读取 `Experiment.status`，取值为 `pending`、`running`、`cancelling`、`completed`、`failed`、`cancelled`。新建实验初始为 `pending`，开始处理 Job 后变为 `running`。全部 Job 进入终态后，实验变为 `completed`，单个 Job 的成功或失败可从 `progress` 查看。
- `execution_config` 返回已保存的 Runner ID、目标标识和超时，不查询实时在线状态，也不返回 Runner Token、Agent URL 或鉴权请求头。历史实验的配置为空时返回 `{}`，不填造执行目标。
- `updated_at` 是实验记录本身的最后更新时间，不保证每次 Job 状态变化都会刷新。

### 列表与详情的 `progress`

| 字段 | 计算口径 |
| --- | --- |
| `example_count` | 该实验固定的样本修订关联数 |
| `job_count` | 该实验下 `ExperimentRun` 的实际行数；新建 V1 实验等于 `example_count × repetitions` |
| `queued`、`assigned`、`running` | 各对应状态的 Job 数 |
| `succeeded`、`failed`、`cancelled` | 各对应终态的 Job 数 |
| `unknown` | 执行情况不明的 Job 数；不归入成功或失败 |

计数均为非负整数，没有该状态时返回 `0`。各 Job 状态计数之和等于 `job_count`。按 **Job** 聚合，同一 Job 的多个 Attempt 不会重复计数；`succeeded` 表示 Task 执行成功，不代表答案正确或评分已完成。逐条运行结果和评分明细留给后续分页接口。

## 错误响应

沿用 `{ "error": { "code": "…", "message": "…" } }`，不回显原始请求、凭据或底层异常。示例：

```json
{
  "error": {
    "code": "dataset_version_not_found",
    "message": "数据集版本不存在"
  }
}
```

| HTTP 状态 | `error.code` | 场景 |
| --- | --- | --- |
| 401 | `not_authenticated` | 未登录或会话失效 |
| 403 | `csrf_invalid` / `origin_forbidden` | 创建请求未通过 CSRF 或来源检查，复用现有鉴权层 |
| 404 | `dataset_not_found` | 数据集不存在或不可访问 |
| 404 | `dataset_version_not_found` | 指定版本不存在、属于其他数据集，或该数据集没有可选版本 |
| 404 | `experiment_not_found` | 实验不存在或不属于当前用户 |
| 404 | `runner_not_found` | Runner 不存在、已删除或不属于当前用户 |
| 409 | `runner_disabled` | 当前用户拥有的 Runner 已禁用 |
| 422 | `invalid_request` | 请求体、ID、分页或字段取值不合法 |
| 422 | `empty_experiment_dataset` | 选定版本没有有效样本 |
| 422 | `experiment_job_limit_exceeded` | 样本数乘重复次数超过单次创建上限 |
| 503 | `service_unavailable` | 必要的数据库或登录会话存储不可用 |

创建后由 Scheduler 自动派发，无需单独启动。取消实验、逐条结果查询和评分属于后续接口。

调试前需有已登录的用户、归属该用户的版本化数据集和可用 Runner。当前未提供数据集创建接口，可先通过开发环境种子数据准备；服务启动时不会自动创建或迁移 PostgreSQL 表，见[数据库说明](../database.md)。
