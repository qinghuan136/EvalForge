# EvalForge 后端接口文档

本文覆盖当前 25 个浏览器 REST 接口和 1 个 Runner WebSocket 入口。服务启动后可用 `/docs` 查看 Swagger UI，用 `/openapi.json` 获取 REST 类型定义。

## 通用约定

- **登录 Cookie**：由浏览器收发，生产默认名为 `__Host-evalforge_session`（`HttpOnly`、`Secure`、`SameSite=Lax`）。前后端跨源时使用 `credentials: "include"`，后端配置允许的前端 Origin；Cookie 仍受浏览器同站策略限制。
- **CSRF**：标注「CSRF」的接口需带 `X-CSRF-Token`，后端还校验 `Origin` 或 `Referer`。先调用 `GET /api/v1/auth/csrf` 获取 Token，登录后改用登录响应的新 Token。写接口中，只有注册、登录、退出无需已登录。
- **请求体**：「JSON」表示 `Content-Type: application/json`；「无」表示不传请求体。除各接口明确列出的参数外，无其他路径或查询参数。
- **阅读示例**：请求行展示 HTTP 方法、路径和查询参数；带 JSON 或表单的请求另列请求体。响应示例只展示响应体，HTTP 状态码和有约定的响应头单独说明。
- **分页**：`page` 为正整数，默认 `1`；`pagesize` 为 `1–100`，默认 `20`。`total` 是总条数，`items` 可能为空。`dataset_id`、`experiment_id` 是正整数；`runner_id` 是 1–128 字符的字符串。响应中的时间为 ISO 8601 字符串。
- **通用错误**：`401 not_authenticated`（需重新登录）、`403 csrf_invalid / origin_forbidden`、`422 invalid_request`、`500 internal_error`、`503 service_unavailable / session_unavailable`。页面按 HTTP 状态和 `error.code` 分支，`error.message` 用作提示。

```json
{"error":{"code":"runner_offline","message":"请先连接实验指定的 Runner"}}
```

## 账号与会话

### 1. `GET /api/v1/auth/csrf`

- **请求**：Cookie 可选，无请求体。无有效会话时创建匿名会话。
- **响应 `200`**：`{"csrf_token":"<token>"}`。创建匿名会话时同时返回 `Set-Cookie`。
- **其他错误**：`429 rate_limited`。

### 2. `POST /api/v1/auth/register`

- **请求**：会话 Cookie + CSRF，JSON：`{"username":"demo_user","password":"DemoOnly-2026!pass","display_name":"Demo"}`。
- **字段**：`username` 去首尾空白后转小写，3–64 字符，匹配 `^[a-z0-9][a-z0-9_.-]*$`；`password` 15–128 字符；`display_name` 可省略或为 `null`，非空值须为非空白字符串且最多 100 字符。
- **响应 `201`**：`{"user":{"id":1,"username":"demo_user","display_name":"Demo"}}`。注册后需单独登录。
- **其他错误**：`409 username_exists`、`429 rate_limited`。

### 3. `POST /api/v1/auth/login`

- **请求**：会话 Cookie + CSRF，JSON：`{"username":"demo_user","password":"DemoOnly-2026!pass"}`。密码字段接受 1–128 字符。
- **响应 `200`**：`{"user":{"id":1,"username":"demo_user","display_name":"Demo"},"session_expires_at":"2026-11-13T08:00:00Z","csrf_token":"<new-token>"}`；通过 `Set-Cookie` 更换会话。
- **其他错误**：`401 invalid_credentials`、`429 rate_limited`。

### 4. `GET /api/v1/auth/me`

- **请求**：登录 Cookie，无请求体。
- **响应 `200`**：`{"user":{"id":1,"username":"demo_user","display_name":"Demo"},"session_expires_at":"2026-11-13T08:00:00Z"}`。`user.display_name` 可为 `null`；需要 CSRF Token 时另调 `GET /api/v1/auth/csrf`。

### 5. `POST /api/v1/auth/logout`

- **请求**：携带当前会话 Cookie（如有）和 CSRF，无请求体。会话失效时，仍需传格式有效的 CSRF Token。
- **响应 `204`**：无响应体；清除当前 Cookie。

### 6. `POST /api/v1/auth/logout-all`

- **请求**：登录 Cookie + CSRF，无请求体。
- **响应 `204`**：无响应体；让该账号的所有浏览器会话失效，并清除当前 Cookie。

### 7. `POST /api/v1/auth/password`

- **请求**：登录 Cookie + CSRF，JSON：`{"current_password":"DemoOnly-2026!pass","new_password":"DemoOnly-2026!next"}`。当前密码字段接受 1–128 字符，新密码须为 15–128 字符。
- **响应 `204`**：无响应体；所有浏览器会话失效并清除当前 Cookie，需重新登录。
- **其他错误**：`401 invalid_password`、`429 rate_limited`。

## Runner 管理

### 8. `POST /api/v1/runners`

- **请求**：登录 Cookie + CSRF，JSON：`{"name":"本地 Runner"}`。名称去首尾空白后为 1–100 字符。
- **响应 `201`**：

```json
{
  "runner": {"runner_id":"runner-01","name":"本地 Runner","enabled":true,"created_at":"2026-11-12T08:00:00Z"},
  "credential": {"id":1,"token_id":"<token-id>","token":"<runner-token>","expires_at":"2036-11-12T08:00:00Z"},
  "connection": {"websocket_url":"wss://localhost:8000/api/v1/runner/ws"}
}
```

完整 `credential.token` 只在创建响应返回，供用户配置 Runner；换凭证需要删除并重建。

### 9. `GET /api/v1/runners`

- **请求**：登录 Cookie，查询 `page`、`pagesize` 可选，无请求体。例如 `GET /api/v1/runners?page=1&pagesize=20`。
- **响应 `200`**：`{"items":[],"page":1,"pagesize":20,"total":0}`。有数据时，`items` 的每项为 [`RunnerDetail`](#runnerdetail-响应示例)。

### 10. `GET /api/v1/runners/{runner_id}`

- **请求**：登录 Cookie，路径 `runner_id` 必填，无请求体。
- **响应 `200`**：[`RunnerDetail`](#runnerdetail-响应示例)。
- **其他错误**：`404 runner_not_found`；不存在或不属于当前用户。

### 11. `PATCH /api/v1/runners/{runner_id}`

- **请求**：登录 Cookie + CSRF，路径 `runner_id` 必填，JSON：`{"name":"办公电脑"}`。名称限制同创建。
- **响应 `200`**：更新后的 [`RunnerDetail`](#runnerdetail-响应示例)。
- **其他错误**：`404 runner_not_found`。

### 12. `DELETE /api/v1/runners/{runner_id}`

- **请求**：登录 Cookie + CSRF，路径 `runner_id` 必填，无请求体。
- **响应 `204`**：无响应体；删除 Runner 并吊销凭证，重复删除自己的同一 Runner 仍可成功。
- **其他错误**：`404 runner_not_found`。

### RunnerDetail 响应示例

```json
{
  "runner_id": "runner-01",
  "name": "本地 Runner",
  "enabled": true,
  "created_at": "2026-11-12T08:00:00Z",
  "updated_at": "2026-11-12T08:00:00Z",
  "last_seen_at": null,
  "connection": {"online": false, "phase": "disconnected", "capabilities": []}
}
```

`last_seen_at` 是时间字符串或 `null`；`phase` 为 `disconnected | connected | syncing | ready`。列表和详情均不返回凭证。

[`connection.capabilities`](#runner-能力) 来自 Redis 中的当前会话，离线时返回 `[]`。

## 数据集导入

### 13. `POST /api/v1/datasets/import`

- **请求**：登录 Cookie + CSRF；`multipart/form-data`，表单字段如下。
- **响应 `201`**：`{"dataset_id":12,"dataset_version_id":3,"example_count":4}`。同时创建数据集及第一个版本。

| 字段 | 类型与要求 |
| --- | --- |
| `name` | 字符串，必填；去首尾空白后 1–100 字符。 |
| `description` | 字符串，可省略；最多 2,000 字符。 |
| `format` | 字符串，必填；`csv` 或 `jsonl`。 |
| `file` | 文件，必填；UTF-8，可带 BOM，最大 5 MiB、最多 10,000 条样本。 |
| `input_keys` | CSV 至少选一列。每列用同名字段提交一次。 |
| `output_keys`、`metadata_keys` | CSV 可选；同样按列重复字段，三组不得重叠。 |

CSV 有表头，最多 256 列，选中列的值按字符串保存。JSONL 不传列映射，每个非空行形如 `{"input":{"question":"你好"},"output":{"answer":"你好"},"metadata":{}}`：`input` 必填，另两项可省略且默认 `{}`，三项都须为 JSON 对象。数据集里的 `output` 是参考答案。

```js
const body = new FormData();
body.append("name", "问答测试集");
body.append("format", "csv");
body.append("file", file); // 文件选择器中的 File
body.append("input_keys", "question");
body.append("input_keys", "context");
body.append("output_keys", "answer");

await fetch("/api/v1/datasets/import", {
  method: "POST",
  credentials: "include",
  headers: { "X-CSRF-Token": csrfToken },
  body,
});
```

浏览器发送 `FormData` 时自动设置带 boundary 的 `Content-Type`。其他错误：`400 invalid_dataset_upload`、`409 dataset_name_conflict`、`413 dataset_file_too_large / dataset_too_many_examples`、`415 unsupported_dataset_upload`、`422 invalid_dataset_file / invalid_dataset_encoding / invalid_dataset_columns / empty_dataset_file`。行内容有误时 `error.message` 会指出行号。见[导入示例](数据集导入.md)。

## 评分器与数据集配置

### 14. `GET /api/v1/evaluators/builtin`

- **请求**：登录 Cookie，无请求体。
- **响应 `200`**：规则数组。下面只展示其中一项；`input_schema` 是该规则的 JSON Schema，可用于生成配置表单。

```json
[
  {
    "key": "exact_match",
    "description": "Checks whether the actual text exactly matches the expected text.",
    "input_schema": {
      "title": "ExactMatchEvaluator",
      "type": "object",
      "additionalProperties": false,
      "properties": {
        "expected": {"title":"Expected","type":"string"},
        "actual": {"title":"Actual","type":"string"},
        "case_sensitive": {"title":"Case Sensitive","type":"boolean","default":true}
      },
      "required": ["expected","actual"]
    },
    "output_configs": [{
      "name": "exact_match",
      "type": "CATEGORICAL",
      "optimization_direction": "MAXIMIZE",
      "values": [{"label":"true","score":1.0},{"label":"false","score":0.0}]
    }]
  }
]
```

### 15. `GET /api/v1/datasets/{dataset_id}/evaluators`

- **请求**：登录 Cookie，路径 `dataset_id` 必填，查询 `page`、`pagesize` 可选，无请求体。
- **响应 `200`**：`{"items":[],"page":1,"pagesize":20,"total":0}`。有数据时，`items` 的每项与下方创建配置的响应一致。
- **其他错误**：`404 dataset_not_found`。

### 16. `POST /api/v1/datasets/{dataset_id}/evaluators`

- **请求**：登录 Cookie + CSRF，路径 `dataset_id` 必填，JSON：

```json
{
  "name": "答案匹配",
  "evaluator_key": "exact_match",
  "input_mapping": {
    "path_mapping": {"actual":"$.output.answer","expected":"$.reference.answer"},
    "literal_mapping": {"case_sensitive":false}
  }
}
```

`name` 去首尾空白后 1–100 字符，在同一数据集内唯一；`evaluator_key` 取自规则目录；`description` 可省略或传 `null`，最多 2,000 字符。`input_mapping` 必填；其内两张表各自可省略（默认空对象）。规则的必填参数须有映射，每个参数只能用路径或固定值之一。路径根节点可为 `$.input`、`$.reference`、`$.output`、`$.metadata`，其中 `reference` 是参考答案，`output` 是 Agent 实际输出。

- **响应 `201`**：

```json
{
  "dataset_evaluator_id": 5,
  "dataset_id": 12,
  "name": "答案匹配",
  "description": null,
  "evaluator_key": "exact_match",
  "input_mapping": {
    "path_mapping": {"actual":"$.output.answer","expected":"$.reference.answer"},
    "literal_mapping": {"case_sensitive":false}
  },
  "output_configs": [{
    "name": "答案匹配",
    "type": "CATEGORICAL",
    "optimization_direction": "MAXIMIZE",
    "values": [{"label":"true","score":1.0},{"label":"false","score":0.0}]
  }]
}
```

其他错误：`404 dataset_not_found / builtin_evaluator_not_found`、`409 dataset_evaluator_name_conflict / builtin_evaluator_name_conflict`、`422 invalid_input_mapping`。见[映射规则详情](数据集评分配置.md)。

## 实验

### 17. `POST /api/v1/datasets/{dataset_id}/experiments`

- **请求**：登录 Cookie + CSRF，路径 `dataset_id` 必填，JSON：

```json
{
  "name": "问答回归测试",
  "description": "验证问答输出",
  "dataset_version_id": 3,
  "repetitions": 1,
  "metadata": {"source":"web"},
  "dataset_evaluator_ids": [5],
  "execution_config": {
    "runner_id": "runner-01",
    "agent_target_id": "qa-agent",
    "timeout_seconds": 60,
    "stream_output": false
  }
}
```

| 字段 | 要求 |
| --- | --- |
| `name` | 必填；去首尾空白后 1–100 字符。 |
| `description`、`metadata` | 可选；描述最多 2,000 字符，可为 `null`；元数据为 JSON 对象，默认 `{}`。 |
| `dataset_version_id` | 可选的正整数；省略取最新版本，不可传 `null`。 |
| `repetitions` | 1–100 的整数，默认 1；样本数 × 重复次数最多 10,000。 |
| `dataset_evaluator_ids` | 正整数数组，默认 `[]`；最多 100 项且不重复。 |
| `execution_config` | 必填；`runner_id` 和 `agent_target_id` 必填，均为 1–128 字符。`agent_target_id` 对应 Runner 本地配置。`timeout_seconds` 默认 60，范围 `(0, 3600]`；`stream_output` 为布尔值，默认 `false`。 |

- **响应 `201`**：[`ExperimentDetail`](#experimentdetail-响应示例)；响应头 `Location: /api/v1/experiments/{experiment_id}`。
- **校验**：普通和流式实验都要求指定 Runner 属于当前用户、已启用，且在 Redis 中有有效在线会话；流式还要求 `http_json` 和 `http_sse` 能力。可以在线时提交，派发要等 `ready`。
- **其他错误**：`404 dataset_not_found / dataset_version_not_found / runner_not_found / dataset_evaluator_not_found`；`409 runner_disabled / runner_offline / runner_streaming_unsupported`；`422 empty_experiment_dataset / experiment_job_limit_exceeded`；`503 runner_session_unavailable`。

### 18. `GET /api/v1/datasets/{dataset_id}/experiments`

- **请求**：登录 Cookie，路径 `dataset_id` 必填，查询 `page`、`pagesize` 可选，无请求体。
- **响应 `200`**：`{"items":[],"page":1,"pagesize":20,"total":0}`。每项为 `ExperimentSummary`：下方详情去掉 `description`、`metadata`、`execution_config`、`evaluators`。
- **其他错误**：`404 dataset_not_found`。

### 19. `GET /api/v1/experiments/{experiment_id}`

- **请求**：登录 Cookie，路径 `experiment_id` 必填，无请求体。
- **响应 `200`**：[`ExperimentDetail`](#experimentdetail-响应示例)。前端可轮询本接口获取最新汇总进度。
- **其他错误**：`404 experiment_not_found`。

### 20. `POST /api/v1/experiments/{experiment_id}/cancel`

- **请求**：登录 Cookie + CSRF，路径 `experiment_id` 必填，无请求体。
- **响应 `200`**：[`ExperimentDetail`](#experimentdetail-响应示例)。排队 Job 立即取消，正在执行的 Job 异步取消；可能先返回 `cancelling`。重复调用安全；终态实验返回原状态。
- **其他错误**：`404 experiment_not_found`。

### ExperimentDetail 响应示例

```json
{
  "experiment_id": 42,
  "dataset_id": 12,
  "dataset_version_id": 3,
  "name": "问答回归测试",
  "status": "pending",
  "repetitions": 1,
  "progress": {
    "example_count": 4, "job_count": 4,
    "queued": 4, "assigned": 0, "running": 0, "succeeded": 0,
    "failed": 0, "cancelled": 0, "unknown": 0,
    "evaluations": {"expected": 0, "completed": 0, "errors": 0}
  },
  "created_at": "2026-11-12T08:00:00Z",
  "updated_at": "2026-11-12T08:00:00Z",
  "description": "验证问答输出",
  "metadata": {"source":"web"},
  "execution_config": {
    "runner_id": "runner-01", "agent_target_id": "qa-agent",
    "timeout_seconds": 60, "stream_output": false
  },
  "evaluators": [{
    "dataset_evaluator_id": 5,
    "name": "答案匹配",
    "description": null,
    "evaluator_key": "exact_match",
    "input_mapping": {
      "path_mapping": {"actual":"$.output.answer","expected":"$.reference.answer"},
      "literal_mapping": {"case_sensitive":false}
    },
    "output_configs": [{
      "name":"答案匹配", "type":"CATEGORICAL", "optimization_direction":"MAXIMIZE",
      "values":[{"label":"true","score":1.0},{"label":"false","score":0.0}]
    }]
  }]
}
```

`status` 为 `pending | running | cancelling | completed | failed | cancelled`。`evaluators` 是创建时固定的评分配置快照（每项不含 `dataset_id`；未配置时为 `[]`）。旧实验的 `execution_config` 可能缺少 Runner、目标或超时字段，`stream_output` 仍会返回，默认 `false`。见[实验接口详情](实验创建与查询.md)。

详情响应的 `progress.evaluations` 提供[评分进度](#实验评分进度)；实验列表仍只统计 Job 执行状态。

## Runner WebSocket

### 21. `WS /api/v1/runner/ws`

- **握手请求**：使用创建 Runner 时返回的 `connection.websocket_url`，携带 `Authorization: Bearer <runner-token>`，无查询参数、无请求体。默认用 WSS；本地回环可显式允许 WS。
- **握手响应 `101`**：升级连接，无 JSON 响应体。未升级时可能返回 `400 invalid_connection_url`、`401 invalid_runner_credential`、`403 wss_required / origin_forbidden` 或 `503 service_unavailable`；不支持自定义握手拒绝响应的服务器统一以 HTTP `403` 拒绝。
- **连接内消息**：JSON-RPC 2.0 文本，单条最多 1 MiB。请求为 `{"jsonrpc":"2.0","method":"...","params":{},"id":1}`；响应为 `{"jsonrpc":"2.0","result":{},"id":1}`，失败时用 `error: {code, message}` 代替 `result`。通知无 `id`、无响应。

下表只列业务 `params` 和 `result`。`AttemptKey` 为 `{job_id: string, attempt_id: string}`；各方法的完整报文见 [Runner JSON-RPC 协议](../EvalForge_Runner_JSON-RPC_Protocol_v1.md)。

| 方向 | 方法 | 请求 `params` | 成功 `result` |
| --- | --- | --- | --- |
| Runner → 云端 | `runner.hello` | `{runner_id, version, capabilities: string[], max_concurrent_jobs: 1}` | `{session_id, status: "ready"}`；此处只表示握手通过。 |
| Runner → 云端 | `runner.sync` | `{runner_id, active_jobs, pending_results}`；活跃项为 `AttemptKey` + `status`，待传项为完整 `jobs.complete` 参数。 | `{jobs: [{job_id, attempt_id, action}]}`；`action` 为 `continue`、`cancel` 或 `retry_upload`。 |
| Runner → 云端 | `runner.ready` | `{session_id}` | `{session_id, status: "ready"}`；此后会话可接收派发。 |
| 云端 → Runner | `jobs.dispatch` | `AttemptKey` + `{agent_target_id, example_id, input, timeout_seconds, stream_output?}` | `{accepted: boolean, reason?: string}`；仅表示是否接单。 |
| 云端 → Runner | `jobs.cancel` | `AttemptKey` + `{reason}` | `{accepted: boolean, reason?: string}`；受理不等于取消完成。 |
| Runner → 云端 | `jobs.started` | `AttemptKey` | `{acknowledged: true}`。 |
| Runner → 云端 | `jobs.complete` | `AttemptKey` + `{status, output, duration_ms, http_status, error}`；状态为 `succeeded`、`failed` 或 `cancelled`，`http_status` 可为 `null`，`error` 为 `null` 或 `{code, message}`。 | `{acknowledged: true}`；云端保存后才确认。 |
| Runner → 云端 | `jobs.output_chunk` | `AttemptKey` + `{chunks: [{seq, text}]}`；每批 1–16 片。 | 无；这是通知，最终输出仍以 `jobs.complete` 为准。 |

## 数据集查询

以下三个 GET 接口均需要登录 Cookie，不需要 CSRF。只能读取当前用户的数据；资源不存在或不属于当前用户时返回对应的 `404`。分页沿用通用约定。

### 22. `GET /api/v1/datasets`

**请求结构**：无路径参数和请求体。查询参数 `page`、`pagesize` 均可省略。

```http
GET /api/v1/datasets?page=1&pagesize=20
```

**成功响应 `200`**：

```json
{
  "items": [
    {
      "dataset_id": 12,
      "name": "问答测试集",
      "description": "用于回归验证",
      "latest_version_id": 3,
      "created_at": "2026-11-12T08:00:00Z",
      "updated_at": "2026-11-12T08:00:00Z"
    }
  ],
  "page": 1,
  "pagesize": 20,
  "total": 1
}
```

`description`、`latest_version_id` 可为 `null`。按 `created_at` 倒序，时间相同时按 `dataset_id` 倒序。

### 23. `GET /api/v1/datasets/{dataset_id}`

**请求结构**：`dataset_id` 为必填正整数。无查询参数和请求体。

```http
GET /api/v1/datasets/12
```

**成功响应 `200`**：

```json
{
  "dataset_id": 12,
  "name": "问答测试集",
  "description": "用于回归验证",
  "latest_version_id": 3,
  "created_at": "2026-11-12T08:00:00Z",
  "updated_at": "2026-11-12T08:00:00Z",
  "metadata": {},
  "example_count": 4
}
```

`example_count` 是最新版本的有效样本数，无版本时为 `0`。`metadata` 为 JSON 对象。

**其他错误**：`404 dataset_not_found`。

### 24. `GET /api/v1/datasets/{dataset_id}/examples`

**请求结构**：`dataset_id` 为必填正整数，无请求体。查询参数 `version_id`、`page`、`pagesize` 均可省略。`version_id` 为正整数，省略时使用最新版本；查看历史实验时，可传实验的 `dataset_version_id`。

```http
GET /api/v1/datasets/12/examples?version_id=3&page=1&pagesize=1
```

**成功响应 `200`**：

```json
{
  "dataset_id": 12,
  "dataset_version_id": 3,
  "items": [
    {
      "example_id": 101,
      "input": {"question": "法国的首都是哪里？"},
      "output": {"answer": "巴黎"},
      "metadata": {"category": "地理"}
    }
  ],
  "page": 1,
  "pagesize": 1,
  "total": 4
}
```

`input`、`output`、`metadata` 均为 JSON 对象；这里的 `output` 是参考输出。取不晚于所选版本的每条样本的最新修订，排除在该版本已删除的样本，按 `example_id` 升序。无版本且未指定 `version_id` 时，`dataset_version_id` 为 `null`，`items` 为空，`total` 为 `0`。

**其他错误**：`404 dataset_not_found / dataset_version_not_found`。显式指定的版本不存在或不属于该数据集时，返回 `dataset_version_not_found`。

## Job 查询

两个接口均需要登录 Cookie，不需要 CSRF。只能查看当前用户的实验，分页沿用通用约定。

### 25. `GET /api/v1/experiments/{experiment_id}/jobs`

**请求结构**：`experiment_id` 为必填正整数，无请求体。查询参数 `page`、`pagesize`、`status` 均可省略；`status` 可为 `queued | assigned | running | succeeded | failed | cancelled | unknown`，省略则不过滤。

```http
GET /api/v1/experiments/42/jobs?status=succeeded&page=1&pagesize=1
```

**成功响应 `200`**：`items` 的每项为 `JobSummary`。

```json
{
  "items": [
    {
      "job_id": "e097eaf1-bcae-4585-988c-0a05f2860abd",
      "example_id": 101,
      "repetition_number": 1,
      "status": "succeeded",
      "duration_ms": 342.5,
      "http_status": 200,
      "evaluation_progress": {"expected": 1, "completed": 1, "errors": 0}
    }
  ],
  "page": 1,
  "pagesize": 1,
  "total": 2
}
```

按 Job 创建顺序返回，`total` 为筛选后的总数。`duration_ms` 和 `http_status` 可为 `null`；完整输入、输出和评分明细只在详情返回。

**其他错误**：`404 experiment_not_found`。

### 26. `GET /api/v1/experiments/{experiment_id}/jobs/{job_id}`

**请求结构**：`experiment_id` 为必填正整数，`job_id` 为列表返回的必填字符串（1–128 字符）。无查询参数和请求体。

```http
GET /api/v1/experiments/42/jobs/e097eaf1-bcae-4585-988c-0a05f2860abd
```

**成功响应 `200`**：

```json
{
  "job_id": "e097eaf1-bcae-4585-988c-0a05f2860abd",
  "example_id": 101,
  "repetition_number": 1,
  "status": "succeeded",
  "duration_ms": 342.5,
  "http_status": 200,
  "evaluation_progress": {"expected": 1, "completed": 1, "errors": 0},
  "input": {"question": "法国的首都是哪里？"},
  "reference": {"answer": "巴黎"},
  "metadata": {"category": "地理"},
  "output": {"answer": "巴黎"},
  "error": null,
  "started_at": "2026-11-12T08:01:02Z",
  "ended_at": "2026-11-12T08:01:02.343Z",
  "evaluations": [
    {"name": "答案匹配", "score": 1.0, "label": "true", "explanation": null, "error": null}
  ]
}
```

- `input`、`reference`、`metadata` 取自实验固定的样本修订。`output` 是 Agent 实际输出，可为任意 JSON 值（包括 `null`）；用 `status` 判断是否执行完毕。
- Job 的 `error` 为 `null` 或 `{code, message}`；`started_at`、`ended_at` 可为 `null`。
- `evaluations` 只包含实验配置中已保存的评分，按创建实验时的评分器顺序返回，没有记录时为 `[]`。每项除 `name` 外均可为 `null`；其中 `error` 非空时是错误说明字符串，低分仍是正常结果。

**其他错误**：`404 experiment_not_found / job_not_found`。Job 不属于指定实验时返回 `job_not_found`。

## 实验评分进度

**请求结构**：沿用 [创建实验](#17-post-apiv1datasetsdataset_idexperiments)、[实验详情](#19-get-apiv1experimentsexperiment_id) 和 [取消实验](#20-post-apiv1experimentsexperiment_idcancel) 的现有请求，不新增参数。

**成功响应**：沿用 `ExperimentDetail`，在原有 `progress` 中增加 `evaluations`。以下展示响应中的完整 `progress` 对象；其余字段见 [ExperimentDetail 示例](#experimentdetail-响应示例)。

```json
{
  "example_count": 4,
  "job_count": 4,
  "queued": 0,
  "assigned": 0,
  "running": 0,
  "succeeded": 4,
  "failed": 0,
  "cancelled": 0,
  "unknown": 0,
  "evaluations": {"expected": 4, "completed": 3, "errors": 1}
}
```

- Job 列表和详情中的 `evaluation_progress` 使用相同结构，仅统计当前 Job。
- `expected`：当前已成功的 Task 对应的评分项数，按实验固定的评分配置计算；随 Task 成功增加。
- `completed`：已保存的评分项数，包含评分错误；`errors` 是其中记录了错误的项数。没有配置评分时三项均为 `0`。
- 运行中的实验可用 `expected - completed` 显示当前待评分数。实验取消后仍可显示已保存评分，剩余差额不代表还会继续执行。

## Runner 能力

**请求结构**：沿用 [Runner 列表](#9-get-apiv1runners)、[Runner 详情](#10-get-apiv1runnersrunner_id) 和 [Runner 改名](#11-patch-apiv1runnersrunner_id) 的现有请求，不新增参数。

**成功响应 `200`**：在 `RunnerDetail` 的 `connection` 中新增 `capabilities: string[]`，取自 Redis 的当前会话注册。列表的每个 `items` 元素使用相同结构。

```json
{
  "runner_id": "runner-01",
  "name": "本地 Runner",
  "enabled": true,
  "created_at": "2026-11-12T08:00:00Z",
  "updated_at": "2026-11-12T08:00:00Z",
  "last_seen_at": "2026-11-12T08:00:30Z",
  "connection": {"online": true, "phase": "ready", "capabilities": ["http_json", "http_sse"]}
}
```

离线时，`connection` 为 `{"online":false,"phase":"disconnected","capabilities":[]}`。前端可在 Runner 在线且同时声明 `http_json` 和 `http_sse` 时启用「流式输出」。是否允许创建仍由后端校验。首版继续手填 Runner 本地配置里的 `agent_target_id`。

跨数据集的实验列表、版本列表和浏览器流式预览 SSE 暂未实现。
